# 비트코인 내일 방향, 예측할 수 있을까

업비트 일봉 9년치로 **기술적 분석 지표가 다음날 가격 방향을 예측할 수 있는지** 검증한 기록입니다.
결과를 그대로 재현할 수 있도록 데이터 수집부터 검정까지 전부 공개합니다.

> **결론: 가격 데이터만으로 내일 오를지 내릴지 맞히는 것은, 믿을 만한 수준으로는 되지 않습니다.**
>
> TA-Lib 지표 81개와 캔들패턴 61종을 조건 191개로 만들어 같은 기준으로 검정한 결과는,
> **예측이 불가능하도록 만든 가짜 가격 데이터와 구분되지 않았습니다.**

읽기 쉽게 정리한 글: [StraHub 블로그](https://app.strahub.com/blog)

<details>
<summary>English summary</summary>

Nine years of Upbit daily candles (KRW-BTC, 2017-09 ~ 2026-09) tested for next-day
directional predictability. 191 conditions built from 81 TA-Lib indicators and all 61
candlestick patterns were evaluated under the same regime-controlled criterion.

The headline finding: a momentum signal (RSI > 70) that survived threshold sweeps,
year-by-year splits, execution-assumption changes and an out-of-sample period
**vanished entirely once compared within the same calendar month** (−0.083%,
95% CI [−0.379%, +0.216%]).

Against 20 surrogate price series — block-bootstrapped to preserve volatility
clustering and candle shapes while destroying predictability — the real data produced
*fewer* surviving conditions (40) than the surrogates (43.0 ± 15.1).

All scripts are runnable end to end: `fetch_data.py` pulls the data from Upbit's public
API (no key required). Korean documentation below.
</details>

## 재현 방법

### 1. 설치

```bash
pip install -r requirements.txt
```

`probe1` ~ `probe5` 는 **pandas 와 numpy 만** 있으면 됩니다.
`probe6`, `probe7` 은 TA-Lib 이 필요한데 C 라이브러리를 먼저 깔아야 해서 설치가 까다롭습니다.
안 되면 probe1~5 만 돌려도 핵심 결론은 다 확인됩니다.

### 2. 데이터 받기

```bash
python fetch_data.py
```

업비트 공개 API에서 KRW-BTC 일봉 전체를 받아 `data/ohlcv_data_kst.db` 를 만듭니다.
**인증키가 필요 없습니다.** 약 17번 호출, 10초, 몇 MB.

`probe4` 의 코인 교차검증까지 돌리려면 원화 마켓 전체가 필요합니다 (약 12분).

```bash
python fetch_data.py --all-coins
```

### 3. 실행

```bash
python probe1_baseline.py       # 구간별·조건별 적중률, 손익비
python probe2_validate.py       # 연도별·기간별 분해, 백테스트
python probe3_robustness.py     # 임계값 민감도, 체결 가정, 추세필터 대조
python probe4_crosscoin.py      # 코인 112개 교차검증 (--all-coins 필요)
python probe5_control.py        # ★ 국면 통제 — 결론이 뒤집힌 지점
python probe6_all_indicators.py # 지표 191개 일괄 검정 (TA-Lib 필요)
python probe7_surrogate.py      # ★ 가짜 가격 대조 — 검정 방법 자체를 검증
python probe8_btc_comove.py     # 코인들이 비트코인과 얼마나 같이 움직이나 (--all-coins 필요)
```

`probe8` 은 상장폐지된 코인까지 보려고 `data/delisted_daily.csv` 를 같이 읽습니다.
업비트 공개 API 로는 폐지된 코인의 과거 일봉을 받을 수 없어 저장소에 넣어 두었습니다
(14종, 2023-01 이후). 파일이 없으면 그 절만 건너뜁니다.

### 재현 확인용 기준값

| 스크립트 | 확인할 값 | 기대치 |
|---|---|---|
| probe1 | 관성추종 1일 적중률 | `50.0%` |
| probe4 | 코인 간 평균 상관 | `0.448` |
| probe8 | BTC 와의 상관 중앙값 (118종) | `0.494` |
| probe5 | BTC 같은 달 대비 | `약 -0.08%` |
| probe6 | 조건 수 / 통제 후 생존 | `191개` / `40개` |
| probe7 | 가짜 가격 생존 평균 | `43.0 ± 15.1개` (진짜보다 많음) |

업비트 데이터는 계속 쌓이므로 실행 시점에 따라 소수점 끝자리는 달라집니다.
결론이 바뀔 정도의 차이가 나면 그건 알려 주세요.

## 무엇을 확인했나

데이터: 업비트 KRW-BTC 일봉 약 3,285일 (2017-09-25 ~), 빠진 날짜 0건.
거래비용은 왕복 0.16% (수수료 0.10% + 슬리피지 0.06%)로 계산했습니다.

| 검증 | 결과 |
|---|---|
| 관성추종 1·3·7·14·30일 | 전 구간 95% 신뢰구간이 50%를 포함 — **어느 구간도 안 됨** |
| 역발상 조건 (급락 후 반등, RSI<30, 볼린저 하단) | **전부 무의미** |
| 순발상 조건 (RSI>70, 볼린저 상단, 연속 상승) | 다음날 상승률 57~59% ← **여기까진 긍정적** |
| 임계값 민감도 / 연도별 / 체결 가정 | 전부 통과 |
| 백테스트 | 최대낙폭 −86.8% → −36.8%, Sharpe 0.91 → 1.51 |
| 코인 112개 교차검증 | 방향 적중률 재현 실패 (58/112 = 51.8%), BTC는 57위 |
| 코인 간 독립성 | 평균 상관 0.448 → **실질 독립 표본 약 2개** |
| 동조 구조 (probe8) | 118종 상관 중앙값 0.494, 절반이 0.41~0.56 — **순위 구간은 중앙값 44위** |
| 분산 효과 (probe8) | 등가중 1종목 4.27% → 100종목 2.99%, **30%밖에 안 줄어듦** (무상관이면 0.43%) |
| 위약 인자 (probe8) | BTC 대신 다른 코인을 인자로 써도 0.539 — **BTC 가 중심인 것도 아님** |
| **국면 통제 (probe5)** | **−0.083%, 95% CI [−0.379%, +0.216%] → 효과 0** |
| 변동성 5분위 이중 통제 | **5개 구간 전부 신뢰구간이 0 포함, 부호도 무작위** |
| 전 지표 일괄 (probe6) | 191개 중 통제 전 82개(42.9%) → 통제 후 40개(22종류) |
| **플라시보 검정 (probe7)** | **가짜 가격 20개: 43.0 ± 15.1개 — 진짜(40개)보다 많음** |

### 백테스트 결과를 어떻게 읽어야 하나

낙폭이 −86.8%에서 −36.8%로 줄어든 것은 실재하지만 **예측이 아니라 회피**입니다.
"오르고 있을 때만 보유"는 결과적으로 하락장에 시장 밖에 있게 만듭니다. 미래를 맞혀서가
아니라 이미 떨어진 것을 보고 빠지는, 뒤늦은 반응입니다. 단순한 이동평균 필터
(MA20 > MA60)도 낙폭을 −68%로 줄였습니다. 특정 지표가 뛰어나서가 아니라는 뜻입니다.

## 결론이 두 번 뒤집혔습니다

이 저장소의 핵심은 결론보다 **뒤집힌 과정**입니다.

### 1차 — probe3까지의 긍정적 결과가 probe5에서 무너짐

RSI>70 신호는 임계값을 55~80으로 바꿔도, 연도별로 나눠도(9년 중 8년), 체결 가정을 바꿔도
유지됐습니다. 백테스트 성적도 좋았습니다. **그런데 신호가 나온 날들이 언제 몰려 있는지를
확인하지 않았습니다.**

상승장에 몰려 있었습니다. 같은 달의 다른 날들하고만 비교하자 차이가 사라졌습니다.
지표는 "좋은 달"을 사후에 지시했을 뿐, 그 달 안에서 어느 날이 좋은지는 구분하지 못했습니다.

### 2차 — probe6의 귀무분포 계산이 틀렸고 probe7이 잡아냄

probe6은 자체적으로 "우연히 기대되는 생존 개수"를 계산해 `5.4개`라는 값을 얻었고,
40개가 살아남았으니 유의하다(`z = +7.41`)고 판정했습니다. **그 계산이 틀렸습니다.**
SMA·EMA·WMA·TRIMA 처럼 사실상 같은 신호인 지표들을 독립된 시도로 셌기 때문입니다.

이상하다는 단서를 준 것은 통계가 아니라 **생존 목록의 모순**이었습니다.

```
MA   상위20% (상승추세)  +0.343%     APO 하위20% (하락추세)  +0.294%
MACD 상위20% (상승추세)  -0.091%     APO 상위20% (상승추세)  -0.230%
```

같은 국면을 가리키는 지표들이 반대 부호를 냈습니다. probe7에서 예측 가능성이 설계상 0인
가짜 가격에 같은 절차를 돌리자 실제 기댓값은 **43개**로 나왔습니다. 여덟 배 차이입니다.

> **교훈: 조건이 수백 개일 때는 우연 기댓값을 직접 계산하려 들지 말고, 신호가 없는 것이
> 확실한 데이터에 검증 절차를 통째로 돌려서 맞춰 보라.**

## 스크립트

| 파일 | 하는 일 |
|---|---|
| `fetch_data.py` | 업비트 공개 API에서 일봉을 받아 SQLite 생성 |
| `probe1_baseline.py` | 구간별(1·3·7·14·30일) 적중률, 조건 11종, 손익비 |
| `probe2_validate.py` | 연도별 분해, 기간 분할, 비겹침 표본, 백테스트 |
| `probe3_robustness.py` | 임계값 민감도 스윕, 체결 가정 3종, 추세필터 대조 |
| `probe4_crosscoin.py` | 코인 112개 교차검증, 생존편향 점검, 독립성 |
| `probe5_control.py` | **국면 통제** — 같은 달 내 비교, 변동성 5분위 이중 통제 |
| `probe6_all_indicators.py` | TA-Lib 지표 81개 + 캔들패턴 61종 → 조건 191개 일괄 검정 |
| `probe7_surrogate.py` | **플라시보 검정** — 가짜 가격으로 검정 방법 자체를 검증 |

### 검증 설계에서 지킨 것

- **미래 정보 차단** — 모든 지표는 해당일 종가 마감까지의 정보로만 계산. 음수 shift는
  정답 라벨을 만드는 한 곳에만 등장합니다.
- **미완성 캔들 제외** — 오늘 날짜 캔들은 아직 마감 전이라 자동으로 뺍니다. 거래량이
  최근 중앙값의 20% 미만이어도 뺍니다. 이걸 빼먹으면 조용한 데이터 오염이 됩니다.
- **자기상관 보정** — 연속된 날은 독립이 아니므로 블록 부트스트랩과 블록 평균 t통계를 씁니다.
- **다중비교** — 조건이 많을수록 우연히 좋아 보이는 것도 늘어납니다. probe7이 이를 보정합니다.

## 한계

- **9년, 코인 1종, 대부분 상승장**이었습니다. 오래 횡보하는 시장이 데이터에 충분하지 않습니다.
- "같은 달 비교"는 비교 기준이 되는 달 평균에 신호를 만들어 낸 급등일 자체가 섞입니다.
  그래서 일부 결과가 음수로 나오지만 계산 구조에서 오는 것이고,
  **확실한 결론은 "차이가 0이다"까지**입니다. "반대로 하면 된다"는 결론은 나오지 않습니다.
- **단일 조건만** 봤습니다. 조합 전략(A AND B), 다중 시간프레임은 시험하지 않았습니다.
  파라미터 최적화는 의도적으로 뺐습니다 — 돌리면 반드시 좋아 보이는 게 나오고 그게 과적합입니다.
  넓히려면 probe7의 플라시보 검정을 **반드시 같이** 돌려야 합니다.
- **파생상품·온체인 데이터**(펀딩비·미결제약정·청산)는 시험하지 않았습니다. 업비트에 없어
  별도 연동이 필요합니다. 가격보다 정보가 많은 쪽이라 가능성은 남아 있습니다.
